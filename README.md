# README.md

# Video Sharing System

中学生向けのローカルLAN型 動画投稿サイト学習システム。

本プロジェクトは、React、Go、PostgreSQLを組み合わせて、普段何気なく利用している「動画投稿サイトの裏側」を実践的かつ安全に学ぶために設計された教育用システムである。

---

## 💡 本システムの教育目的

このシステムは、単にコードの書き方を学ぶためだけのものではない。以下のような「Webシステム全体のダイナミズム」を、手を動かしながら体感することを目的としている。

- **動画配信の裏側:** 大容量ファイルがどのようにサーバーに保存され、ブラウザに小分けにして届くのか（ストリーミングの仕組み）。
- **クライアント・サーバーモデル:** フロントエンド（React）とバックエンド（Go）がどのようにAPIを介して会話をしているのか。
- **UI変更の即時性:** 自分が書き換えたコードが、どのように見た目やユーザー体験（UX）に直結するのかの成功体験の提供。

---

## 🛠️ 主要技術スタック

- **フロントエンド:** React / TypeScript / Vite
- **バックエンド:** Go / Gin Web Framework
- **データベース:** PostgreSQL（本番は Neon）
- **インフラ環境:** Docker / Docker Compose / ローカル実行環境
- **本番デプロイ（任意）:** Vercel（フロント=静的、API=コンテナ）+ Vercel Blob（動画実体）

---

## 🏗️ システム構造（簡易アーキテクチャ）

```txt
[ スマートフォン / カメラ ] （動画撮影）
            │
            ▼
   [ パソコンブラウザ ] ──(動画アップロード / 視聴)──> [ React フロントエンド ]
                                                              │
                                                              │ HTTP API 通信
                                                              ▼
[ ローカルディスクストレージ ] <──(バイナリ保存/配信)─── [ Go API サーバー ]
                                                              │
                                                              │ クエリ実行
                                                              ▼
                                                        [ PostgreSQL ]
```

> **本番（Vercel）構成**: フロントとバックエンドを Vercel の別プロジェクトとして配置し、フロントの rewrite で同一オリジン化する。動画実体はローカルディスクではなく **Vercel Blob** に保存し、大容量アップロードはブラウザから Blob へ直接送る（Vercel のボディ 4.5MB 制限を回避）。詳細は [`back/deployment-and-storage.md`](./back/deployment-and-storage.md)。

## 📂 開発エリアの分離（重要ルール）

本プロジェクトは、受講生（中学生）が安全に試行錯誤できるよう、編集して良いエリアとシステム基盤となる保護エリアを厳格に分離している。

### 🟢 1. 学生編集エリア（Student Editable Area）

学生が自由にデザイン、テキスト、レイアウトを変更し、見た目の変化を楽しめるエリア。

- `frontend/src/components/student/` : UIコンポーネント、デザイン、文言、サムネイル構造の変更
- `frontend/src/styles/` : カラーパレット、CSS、デザインテーマのカスタマイズ

### 🔴 2. システム保護エリア（Protected Internal Area）

システムの安定稼働、通信、動画配信の基盤となる、学生の直接編集を禁止したエリア。

- `frontend/src/api/` & `services/` & `hooks/` : API通信、データ取得、アップロードの隠蔽抽象化レイヤー
- `server/internal/` : データベース操作、HTTPルーティング、ストリーミング配信処理
- `docker/` : コンテナインフラ設定

## 🚀 ローカル開発環境の起動手順

本システムは、教室の環境に合わせて「各言語を直接ローカルで動かす手順」と「Dockerを使用する手順」のどちらにも対応している。

### A. 個別ローカル起動（推奨）

#### 1. フロントエンド（React）の起動

```bash
cd frontend
npm install
npm run dev
```

- 起動後、ブラウザで `http://localhost:5173` にアクセス。

#### 2. バックエンド（Go）の起動

```bash
cd server
go run ./cmd/api
```

- バックエンドAPIサーバーが `http://localhost:8080` で待機。
- ※事前にローカル環境にPostgreSQLが起動している、または接続文字列が設定されている必要がある。

### B. Docker Compose による一括起動

Docker環境が利用可能な場合、以下のコマンド1つでデータベースを含めた全環境が自動構成される。

```bash
docker compose up --build
```

### C. フロントエンドだけ Docker で起動（バックエンドは Vercel）

UIの改善に集中したい場合、フロントエンドだけをコンテナで起動し、バックエンドはVercel上の稼働中APIを利用できる。Node.jsやPostgreSQLのローカル準備は不要である。

```bash
cd front
npm run docker:build   # 初回のみ
npm run docker:dev
```

- 起動後、ブラウザで `http://localhost:5173` にアクセス。
- `front/src/` を編集すると即座にブラウザへ反映される（HMR）。
- **実行手順（コピペ用）:** [`front/実行手順.md`](./front/実行手順.md)
- **仕組み・トラブル詳細:** [`front/DOCKER.md`](./front/DOCKER.md)

> ブラウザから別ドメインのAPIを直接呼ぶとログインCookieが送信されないため、Vite開発サーバーが `/api/*` をVercelのAPIへ中継して同一オリジン化している（本番の `front/vercel.json` の rewrite と同じ考え方）。

## ⚡ 授業・デモ運用のための技術的特徴

- **超高速なフィードバックループ:** フロントエンドにはViteを採用し、学生がコードを書き換えて保存すると、1秒未満でブラウザの見た目が更新される。
- **OOM（メモリ枯渇）を回避するストリーミング設計:** 授業中に多数の学生が同時に数十〜数百メガバイトの動画をアップロード・視聴してもサーバーがクラッシュしないよう、バックエンド（Go）は動画ファイルをメモリに丸ごと読み込まない。`io.Copy` と `HTTP Range Requests` を使用し、ディスクから直接パケット単位でエコに動画をストリーミング配信する設計を徹底している。

## 🛑 非目標（Non-Goals）

このシステムは以下の用途を考慮して**いない**。コードを複雑化させないため、あえて実装を省略または単純化している。

- インターネット経由での不特定多数への公開、大規模スケール、クラウドネイティブな冗長化
- 本格的なユーザー認証（JWTリフレッシュトークン等）や課金、高度なレコメンドアルゴリズム
- HLS等の高度なセグメント動画エンコード（シンプルなMP4/WebM配信に特化）
